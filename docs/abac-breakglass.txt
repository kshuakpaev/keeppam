# KeepPAM: ABAC, 4-eyes, break-glass

## ABAC (уже было + дополнено)

На ACL-привязке актива:

- `required_tags` — теги должны быть и у пользователя, и у актива
- `require_ticket` — при сессии нужен ticket_id
- `require_reason` — при сессии нужна текстовая причина
- `allowed_cidrs` — IP клиента (или CIDR); пусто = любой
- `allowed_countries` — ISO 3166-1 (`RU`) и/или `LAN`; пусто = любая; без MMDB публичный IP → отказ. См. `docs/geoip.txt`
- `allowed_devices` — `TLS` / `WEBAUTHN` / `SSH` / `SPIFFE` / `spiffe://…` / fingerprint; пусто = любое. См. `docs/managed-device.txt`, `docs/spiffe.txt`
- `allowed_namespaces` — kubectl proxy; пусто = любой ns. См. `docs/k8s-pam.txt`
- окно времени / дни недели / JIT `expires_at`

Deny-by-default: нет совпавшей привязки — отказ.

Опциональный **OPA extra deny** после allow: `KEEPPAM_OPA_POLICY`, см. `docs/opa.txt`. OPA не выдаёт доступ.

## Risk-based access

На ACL: `max_risk` (0 = выкл.) + `risk_action` (`deny` | `require_approval` | `require_mfa`).

Score 0–100 (сумма, cap 100). **Connect / JIT request** — факторы окружения. **Операция внутри сессии** — те же факторы + баллы операции (JIT-окно connect-риск не отменяет).

| Factor | Когда | Баллы |
|--------|--------|-------|
| `off_hours` | UTC hour < 6 | 25 |
| `break_glass` | активный break-glass на актив | 40 |
| `failed_logins` | `user.login.failure` за 24ч: 1–2 / 3–7 / ≥8 | 15 / 30 / 45 |
| `concurrent` | pending+active сессии: 3–4 / ≥5 | 10 / 20 |
| `anom_brute` | ≥8 fail за 24ч | 20 |
| `anom_multi` | ≥4 разных актива за 24ч | 15 |
| `op:sql.insert` / `update` / `delete` / `ddl` / `drop` / `export` | SQL DML/DDL/`DROP DATABASE`/COPY | 15 / 20 / 30 / 45 / 100 / 50 |
| `op:k8s.write` / `delete` / `exec` | kubectl create/patch; delete; exec | 20 / 35 / 45 |
| `op:ssh.status` / `restart` / `priv` / `chmod` / `chmod777` / `user` / `firewall` / `destructive` | парсер sudo/su; баллы 5…90, см. `docs/command-risk.txt` |
| `op:http.write` / `delete` | HTTPS/kubectl POST/PUT/PATCH; DELETE | 20 / 35 |

`SELECT` / k8s GET не добавляют баллов и не перепроверяются.

Если score > `max_risk`:
- `deny` — отказ (в т.ч. создать JIT; операция в сессии — отказ без нового JIT)
- `require_approval` — отказ на connect, нужен JIT; после approve **вход** без порога, **операции** (DDL, delete, …) порог всё ещё действует
- `require_mfa` — повторный TOTP/Passkey на connect (см. `docs/adaptive-mfa.txt`); операции внутри сессии как `deny`

Break-glass и admin bypass риск не применяют. JIT-binding (`expires_at`) пропускает только **connect**-риск.

Аудит: `access.risk.evaluated` (`phase=connect|operation`). Сессия: тип `risk`. В `session.denied` / `*.access.denied` — `reason=risk`.

`max_risk=0` — выкл. и connect, и операции.

## 4-eyes / multi-stage JIT

JIT-запрос **нельзя одобрить самому себе** (API + UI). Тот же человек не может закрыть два этапа подряд.

На карточке актива: **JIT согласование**

| Режим | Этапы | Кто жмёт «Одобрить» |
|--------|--------|---------------------|
| Только руководитель (default) | `manager` | `access.approve` |
| Руководитель + ИБ | `manager` → `security` | сначала `access.approve`, затем **другой** пользователь с `access.approve.security` |

Пока не пройдены все этапы, статус `pending`, поле `stage` — текущий. Binding (JIT-окно) создаётся только на последнем этапе.

Роль `security` (seed): `access.approve.security` + `access.request` + `assets.read`. Admin имеет оба права approve, но не может одобрить оба этапа сам.

Аудит: `access.request.stage` (промежуточный), `access.request.approved` (финал). Inbox `jit.stage` на следующий этап.

То же dual-control для checkout секретов.

## Break-glass

Право `access.breakglass` (по умолчанию admin).

1. На карточке актива → «Открыть break-glass» (причина ≥ 20 символов, TTL ≤ 60 мин).
2. Создаётся короткое user-ACL + запись в `break_glass_events`.
3. Аудит `access.breakglass.opened` (severity=critical).
4. Сессия, открытая по активному glass, помечается `break_glass`.
5. Тихий admin-обход ACL (`users.write`) больше не молчит: пишется `session.admin_bypass`.

Список: страница «Запросы».
