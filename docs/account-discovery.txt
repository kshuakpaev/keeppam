# KeepPAM: Account discovery

## SSH (`kind=accounts`)

Обход активных SSH-активов с vault-секретом → `getent passwd` / `/etc/passwd`.
Privileged: uid 0 / root/admin. Импорт — учётка без секрета.

## AD / LDAP (`kind=ad_accounts`, T-09)

LDAP из Config → Auth (тот же bind, что AD group JIT).

Фильтр:

- `(adminCount=1)`
- `memberOf` / nested `LDAP_MATCHING_RULE_IN_CHAIN` для Domain/Enterprise/Schema Admins (+ опц. `group_dns`)

Кандидаты: `protocol=ldap`, `privileged=true`, details `{dn, reasons, member_of}`.
`already_known` — совпадение username или `ad_user_dn` в vault.

Импорт: нужен `target_asset_id` при старте job → `CreateAccount` с `ad_user_dn`, без секрета.

```
POST /api/v1/admin/discovery/jobs
{ "kind": "ad_accounts", "target_asset_id": "…" }
```

## UI

Discovery → «AD privileged (LDAP)» → Кандидаты (новые Domain Admins) → Импорт.

## Ограничения

- Нет WinRM / локальных Windows SAM (только LDAP directory).
- Нужен настроенный LDAP URL + user base DN + bind.
