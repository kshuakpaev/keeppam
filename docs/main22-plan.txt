# KeepPAM: план реализации по docs/main22.txt

Инженерный план закрытия закупочного ТЗ. Не коммерческое предложение (`docs/kp.txt`) и не очередь узких срезов (`docs/main21.txt`).

Источник требований: `docs/main22.txt`. Нумерация **T-xx** — сквозная по абзацам ТЗ (общий блок → функциональный → лицензия).

Статусы:
- **есть** — закрыто текущим кодом, приёмка без доработки;
- **частично** — ядро есть, не хватает формулировки ТЗ;
- **нет** — прямой разрыв.

Оценка трудозатрат — календарные недели при 1–2 инженерах, без параллелизма между зависимыми задачами.

---

## 1. Принципы реализации

1. Не ломать deny-by-default, vault inject и запись из потока (asciicast / `.guac`).
2. Сначала то, что видно в демо согласования и портала (T-16, T-15, T-23), затем HA/архив, затем протоколы.
3. Третьесторонний runtime (guacd, Tesseract, OpenSearch) не выкидывать: в КП раскрыть как bundled runtime единого дистрибутива KeepPAM (T-03).
4. Native RDP / clipboard / printers / drives (T-27, T-29) конфликтуют с DLP по умолчанию — включать только политикой, не «всегда on».
5. Citrix HDX / TN3270 DBCS — SOW; в базе: Telnet, TN3270 MVP, Citrix SOCKS (не guac «на глаз»).
6. Каждый пункт закрывается миграцией + API + UI + audit-событием + строкой в `docs/kp-acceptance.txt` (или приложении к акту).

Порядок фаз (исторический; все закрыты для mid-market):

```
P0 упаковка ✓        →  P1 JIT/портал/4-eyes ✓
P2 запись файлов ✓   →  P3 HA 2+2/3+2 / архив ✓
P4 протоколы/AD ✓    →  P5 appliance / UEBA / Telnet·TN3270·Citrix SOCKS ✓
```

## 4. Общий блок ТЗ (T-01 … T-14)

### T-01. Virtual Appliance
**Статус: есть (pipeline)** — Packer (Ubuntu 24.04 cloudimg) + first-boot wizard + OVA/VHDX export. Compose-дистрибутив P0 без изменений.
**Реализация:** `docs/appliance-ova.txt`, `appliance/`, `scripts/appliance-build.sh`, `appliance-export-ova.sh`, `appliance-export-vhdx.sh`.
**DoD:** на build host с KVM: bundle → `appliance-build` → `.ova`; импорт в vSphere → мастер → login. Hyper-V — T-02 (тот же диск → VHDX).

### T-02. VMware и Hyper-V
**Статус: есть (export)** — `appliance-export-ova.sh` (VMware), `appliance-export-vhdx.sh` (Hyper-V Gen2). Гостевые tools: open-vm-tools в образе; Hyper-V daemons — после импорта по необходимости.
**DoD:** стенд VMware + стенд Hyper-V поднимают control+worker из одного qcow2.

### T-03. Без ПО других производителей
**Статус: есть (срез)** (`NOTICE` + install/upgrade `--pull never` + brand retag `keeppam-*`).
**Реализация:** `docs/runtime-brand.txt`, `deploy/image-brand-map.txt`, `deploy/compose.branded.yml`, `scripts/keeppam-retag.sh`; `KEEPPAM_BRAND=1` в install/upgrade.
**DoD P0:** `keeppam-install.sh` / `keeppam-upgrade.sh` не ходят в registry; на площадке runtime виден как KeepPAM Session Gateway / Search / …  
**Остаток:** пересборка guacd/OS из исходников под своим Dockerfile (не требуется для КП mid-market).

### T-04. Без агентов
**Статус: есть.** SSH/RDP/VNC/HTTP/SQL через шлюз.
**План:** регресс в attack-sim + acceptance. Не ставить агенты «для метаданных окон» (T-32) — снимать из протокола.

### T-05. Трафик сессии, не граббинг экрана
**Статус: есть** (asciicast, `.guac`). OCR — выборочные кадры (T-10), не замена записи.
**План:** в документации и UI явно: «запись из потока»; OCR — индекс, не storage format.

### T-06. Модули access / sessions, scale без остановки
**Статус: есть** (compose 2+2 + Helm, drain, `/livez` `/readyz`).
**Реализация:** `deploy/compose.ha.yml`, `deploy/helm/keeppam/`, `docs/ha.txt`. SIGTERM: readyz=503, SSH drain `KEEPPAM_DRAIN_TIMEOUT`.
**DoD:** kill одного api — login/JIT через edge; stop одного worker — SSH на другом жива.

### T-07. HA-кластер, несколько площадок
**Статус: частично** — 2+2 (`compose.ha.yml`) + 3+2 (`compose.ha3.yml`, Helm api=3). Multi-site async — SOW/P5.
**DoD P3:** убийство одного api — login/JIT живы. **DoD 3+2:** два api down — третий обслуживает edge.

### T-08. Интеграция с AD / глобальными каталогами
**Статус: есть** (LDAP/AD, SAML, OIDC, SCIM).
**План:** чек-лист пилота: bind, group map, nested groups (`docs/groups.txt`). Расширение — T-17 / T-25 / T-48.

### T-09. Discovery неконтролируемых привилегированных УЗ
**Статус: есть (срез)** — SSH passwd + AD LDAP (`ad_accounts`, `088`), `docs/account-discovery.txt`.
**DoD:** в тестовом AD видны Domain Admins, не заведённые в KeepPAM.

### T-10. Встроенный OCR
**Статус: есть** — rus+eng, interval/max_frames в Policy (`079`), `docs/ocr-rdp.txt`. Не live OCR каждого кадра.

### T-11. MFA
**Статус: есть** (TOTP, WebAuthn, step-up).
**План:** не трогать, кроме RADIUS как второго фактора — см. T-48.

### T-12. Журнал и аудит
**Статус: есть** (audit HMAC-chain, SIEM ECS).
**План:** новые фичи (quorum, supervisor, file capture) обязаны писать audit action.

### T-13. Без удалённого подключения производителя
**Статус: есть** (on-prem, нет телеметрии).
**План (P0):** проверка исходящих в attack-sim; в КП явный пункт.

### T-14. Обновления без интернета
**Статус: есть** (tarball + `docker load` + `--pull never` + rollback).
**Реализация:** `docs/offline-update.txt`, `scripts/keeppam-pack.sh`, `keeppam-upgrade.sh`, `keeppam-rollback.sh`.
**DoD:** стенд без registry обновляется с USB (архив `dist/keeppam-*-offline-*.tar.gz`).

## 5. Функциональный блок (T-15 … T-51)

### T-15. Портал EN+RU, запрос доступа без пароля
**Статус: есть** (сценарий JIT+replay; vault inject был раньше).
**Реализация:** `web/src/i18n/` (словарь + cookie `kp_lang`), `Accept-Language`, API `{ error, code }`. См. `docs/i18n.txt`.
**DoD:** полный сценарий JIT+replay на EN без «голых» русских строк в UI. Остальные админ-экраны — RU, не в DoD.

### T-16. Кворум согласующих (2 из 3, 3 из 5)
**Статус: есть** (sequential manager→security **и** quorum N-of-M, миграция `074`).
**Реализация:** `policy/quorum.go`, `requests.go`, карточка актива, заявки. Снимок N/M/группы на заявке. Один голос на актора; deny любым из пула; binding на N-м голосе.
**DoD:** демо 2 из 3: два разных согласующих → binding; третий не нужен; повтор того же — 409.


### T-17. Синхронизация паролей nix / AD / LDAP / Oracle / MSSQL / MySQL
**Статус: есть (срез)** — миграция `082`, `docs/password-sync.txt`.
**Реализация:** `password_sets` + members; rotate set / peer sync при rotate учётки; order directory_first|last; коннекторы SSH/PG/MySQL/MSSQL/LDAP. Oracle — нет.
**DoD:** смена в KeepPAM меняет local unix + AD (+ DB/MSSQL) в одном наборе.

### T-18. Ротация и JIT в многоузловом HA
**Статус: есть** — advisory lock на schedule; `secret_rotation_pending` двухфазный remote→vault (`083`).
**DoD:** kill во время rotate — pending + reconcile не оставляют пароль halfway.

### T-19. Восстановление после split-brain
**Статус: есть (срез)** — `ReconcilePendingRotations`, `docs/ha.txt`.
**DoD:** после сбоя mid-rotate vault и цель сходятся (commit new / drop / force rotate + critical audit).

### T-20. Динамические группы по имени/тегу/платформе/адресу
**Статус: есть** — WHAT-селектор на ACL (`086`): tags/name/hostname/type/cidr, `docs/dynamic-groups.txt`.
**DoD:** новый актив `prod-db-01` с тегом `prod` (+ опц. name glob) покрывается group ACL без ручного bind.

### T-21. Авторотация по правилам
**Статус: есть** (rotation policies).
**План:** UI/доки — явно «правила: TTL, после checkout, после сессии». Регресс.

### T-22. Временной диапазон доступа
**Статус: есть** (JIT TTL, ABAC time window).
**План:** в acceptance — cron window «только пн–пт 09–18».

### T-23. «Четыре глаза» — супервайзер сессии
**Статус: есть** (миграция `075`, право `sessions.supervise`).
**Реализация:** флаг актива `require_supervisor` + опциональная группа; сессия `pending` до `supervisor_approved_at`; connect SSH/RDP/SQL/k8s/HTTPS блокируется; SSH-баннер wait; dual-control; break-glass skip; timeout 15 мин; kill супервайзером.
**DoD:** RDP/SSH не стартует без Authorize; после Approve — сессия идёт; deny/timeout закрывает; свою сессию супервизить нельзя.

### T-24. Break-glass
**Статус: есть.**
**План:** регресс notify (уже `docs/jit-notify.txt` / SMTP).

### T-25. AD-группа на время сессии + rotate после disconnect
**Статус: есть** (миграция `081`, пакет `adjit`, `docs/ad-group-jit.txt`).
**Реализация:** `ad_privileged_group_dn` на активе; `ad_user_dn` на учётке; join на MarkActive; leave на EndHook до MaybeRotateAfterSession; LDAP rotate при group/DN.
**DoD:** user не в группе до сессии, в группе во время, не в группе после; пароль сменён при rotate_after_session; leave fail → critical audit.

### T-26. Прозрачный шлюз
**Статус: есть** (SSH :2222, HTML5 RDP).
**План:** не менять модель; native RDP — T-29.

### T-27. Контроль буфера / принтеров / дисков RDP
**Статус: есть** — `rdp_clipboard|drive|printer` в Policy (`085`), guac handshake, `docs/native-rdp.txt`. Default off.
**DoD:** два профиля: DLP-strict (всё off) и full (clipboard on). Запись clipboard в capture — нет (T-31).

### T-28. Сессия без раскрытия пароля
**Статус: есть.**

### T-29. Любой клиент (PuTTY, Windows RDP, Royal TSX)
**Статус: есть (срез)** — SSH ✓; RDP native через freerdp-proxy + `.rdp` (`rdp_native`, `KEEPPAM_RDP_*`), `docs/native-rdp.txt`.
**DoD SSH:** PuTTY/SecureCRT/Royal TSX — уже. DoD RDP: mstsc → KeepPAM → target без пароля в клиенте (при proxy bin). Citrix — T-33.

### T-30. Шлюз: auth на gateway, затем целевая УЗ
**Статус: есть** (SSH menu / portal).

### T-31. Запись файлов SFTP/SCP/clipboard с восстановлением
**Статус: есть (SCP/SFTP)** — политика `file_transfer=deny|audit|capture`, миграция `078`, `docs/file-transfer.txt`. RDP clipboard — не в этом срезе (T-27).

### T-32. Мониторинг: I/O + метаданные (процессы, окна, файлы)
**Статус: есть (файлы + окна OCR)** — `file_transfer` в replay/transcript; forensic `filename`; заголовок окна = первая строка `screen_text`. Процессы Windows без агента — нет.
**DoD:** forensic фильтр по имени файла; window title — best-effort OCR.

| Протокол        | Сейчас        | Фаза | Подход |
|-----------------|---------------|------|--------|
| SSH + L/R fwd   | есть (+ network PAM) | — | регресс |
| RDP over TLS    | HTML5 guac    | P4 | native — T-29 |
| RemoteApp       | guac + `.rdp` | — | T-34 ✓ `rdp_remote_app*` |
| VNC / SSL       | есть          | — | |

| SFTP/SCP        | capture/audit/deny | — | T-31 ✓ (clipboard RDP — нет) |

### T-34. Приложения RDS / Citrix
**RDS RemoteApp:** есть — поля актива `rdp_remote_app|dir|args` → guac + native `.rdp` (`docs/remoteapp.txt`).
**Citrix:** MVP SOCKS+`.ica` (`docs/citrix-socks.txt`); полный ICA/STA/запись — SOW.

### T-35. GSSAPI / Kerberos в SSH
**Статус: есть (срез)** — миграция `084`, пакет `sshkrb`, `docs/ssh-kerberos.txt`.
**Реализация:** `ssh_auth_mode=gssapi` или `auth_method=gssapi`; password→TGT или keytab; `gssapi-with-mic` на `host/<fqdn>`; поле `krb_spn`.
**DoD:** сессия через KeepPAM на цель с SPN `host/asset` без password auth на sshd (GSSAPI).

### T-36. Live view + kill, свой проигрыватель
**Сейчас:** SSH live-watch + kill; RDP — статус; replay свой (не HTML5 video file).

**DoD:** watch SSH + kill; replay только read-only.

### T-48. Admin auth: AD, RADIUS, x509

## 9. Риски и сознательные исключения

| Риск | Решение |
|------|---------|
| Citrix HDX / STA — годы у Fudo | SOCKS MVP в базе; HDX — SOW / OEM |
| TN3270 полный DBCS | MVP wire ✓; DBCS — SOW |
| Native RDP vs DLP | два профиля политики, default deny clipboard; freerdp-proxy на площадке |
| «Без чужого ПО» vs guacd | bundled runtime + NOTICE, не форк с нуля |
| Метаданные процессов Windows без агента | не обещать; OCR/RAIL best-effort |
| Split-brain паролей | fencing PG + force-rotate (`083`) |
| 3+2 / multi-site | 3+2 compose/Helm ✓; geo async — SOW |

Не делать в базовом плане: полное live OCR, NAC, eIDAS, shell AST, Citrix HDX, Oracle sync (см. `docs/kp.txt` уровень C).
