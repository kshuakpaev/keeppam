# KeepPAM: план реализации по docs/main22.txt

Инженерный план закрытия закупочного ТЗ. Не коммерческое предложение (`docs/kp.txt`) и не очередь узких срезов (`docs/main21.txt`).

Источник требований: `docs/main22.txt`. Нумерация **T-xx** — сквозная по абзацам ТЗ (общий блок → функциональный → лицензия).

Статусы:
- **есть** — закрыто текущим кодом, приёмка без доработки;
- **частично** — ядро есть, не хватает формулировки ТЗ;
- **нет** — прямой разрыв.

Оценка трудозатрат — календарные недели при 1–2 инженерах, без параллелизма между зависимыми задачами.

---

## 1. Принципы реализации

1. Не ломать deny-by-default, vault inject и запись из потока (asciicast / `.guac`).
2. Сначала то, что видно в демо согласования и портала (T-16, T-15, T-23), затем HA/архив, затем протоколы.
3. Третьесторонний runtime (guacd, Tesseract, OpenSearch) не выкидывать: в КП раскрыть как bundled runtime единого дистрибутива KeepPAM (T-03).
4. Native RDP / clipboard / printers / drives (T-27, T-29) конфликтуют с DLP по умолчанию — включать только политикой, не «всегда on».
5. Citrix ICA / TN3270 / Telnet (T-33) — отдельные модули session-worker, не расширение Guacamole «на глаз».
6. Каждый пункт закрывается миграцией + API + UI + audit-событием + строкой в `docs/kp-acceptance.txt` (или приложении к акту).

Порядок фаз:

```
P0 упаковка          →  P1 JIT/портал/4-eyes
P2 запись файлов     →  P3 HA 2+2 / архив
P4 протоколы/AD      →  P5 appliance / 3+2 / UEBA-ML
```

## 4. Общий блок ТЗ (T-01 … T-14)

### T-01. Virtual Appliance
**ТЗ:** готовый программный комплекс (Virtual Appliance).
**Сейчас:** Docker Compose / (частично) k8s. OVA нет.
**План:**
- P0: `scripts/keeppam-install.sh` — один артефакт (образы + compose + `.env.example` + версия).
- P5: сборка OVA (Packer + Ubuntu LTS + docker + first-boot wizard: IP, admin, LDAP).
- Артефакты: `deploy/appliance/`, Packer template, cloud-init, документация first-boot.
**DoD:** импорт OVA в vSphere → мастер → login в портал. Hyper-V — T-02.

### T-02. VMware и Hyper-V
**Сейчас:** нет.
**План (после T-01):** тот же образ → VHDX (qemu-img) + документация Generation 2. Гостевые tools опционально.
**DoD:** стенд VMware + стенд Hyper-V, оба поднимают control+worker.

### T-03. Без ПО других производителей
**Сейчас:** Guacamole, Tesseract, OpenSearch, PostgreSQL, Redis — runtime.
**План (P0):** в КП и `NOTICE` перечислить bundled components; брендировать как KeepPAM Session Gateway / Search / OCR. Не переписывать guacd.
**DoD:** инсталлятор ставит только образы KeepPAM registry; внешних URL в runtime нет.

### T-04. Без агентов
**Статус: есть.** SSH/RDP/VNC/HTTP/SQL через шлюз.
**План:** регресс в attack-sim + acceptance. Не ставить агенты «для метаданных окон» (T-32) — снимать из протокола.

### T-05. Трафик сессии, не граббинг экрана
**Статус: есть** (asciicast, `.guac`). OCR — выборочные кадры (T-10), не замена записи.
**План:** в документации и UI явно: «запись из потока»; OCR — индекс, не storage format.

### T-06. Модули access / sessions, scale без остановки
**Сейчас:** api и session-worker разделены; rolling без документированного runbook.
**План (P3):**
- Helm / compose 2+2: `auth` replicas, `session-worker` replicas, общий PG/Redis.
- Drain: worker перестаёт брать новые сессии, старые доигрывают, SIGTERM.
- Файлы: `deploy/helm/`, `docs/ha.txt`, health `/readyz` vs `/livez`.
**DoD:** `kubectl rollout` / compose scale +1 без обрыва активной SSH-сессии на другом worker.

### T-07. HA-кластер, несколько площадок
**Сейчас:** single compose.
**План:**
- P3: 2 control + 2 worker, один DC, VIP/keepalived или ingress.
- P5: multi-site (active/standby PG + object storage реплика); split-brain — T-19.
**DoD P3:** убийство одного api-контейнера — login и JIT живы. P5 — отдельный SOW.

### T-08. Интеграция с AD / глобальными каталогами
**Статус: есть** (LDAP/AD, SAML, OIDC, SCIM).
**План:** чек-лист пилота: bind, group map, nested groups (`docs/groups.txt`). Расширение — T-17 / T-25 / T-48.

### T-09. Discovery неконтролируемых привилегированных УЗ
**Сейчас:** SSH/passwd scan (`docs/account-discovery.txt`). AD/Windows — нет.
**План (P4):**
- LDAP search `(adminCount=1)` / privileged groups → unmatched local+domain accounts.
- Windows: WinRM/LDAP, не агент.
- UI: очередь «не под PAM» + bind to vault.
**DoD:** в тестовом AD видны Domain Admins, не заведённые в KeepPAM.

### T-10. Встроенный OCR
**Сейчас:** post-session кадры guacenc + Tesseract, `screen_text` (`docs/ocr-rdp.txt`).
**План (P2):** rus+eng, interval в Policy, больше кадров, индекс в forensic. Не live OCR каждого кадра.
**DoD:** на тестовом RDP с текстом «пароль» — hit в session_events.

### T-11. MFA
**Статус: есть** (TOTP, WebAuthn, step-up).
**План:** не трогать, кроме RADIUS как второго фактора — см. T-48.

### T-12. Журнал и аудит
**Статус: есть** (audit HMAC-chain, SIEM ECS).
**План:** новые фичи (quorum, supervisor, file capture) обязаны писать audit action.

### T-13. Без удалённого подключения производителя
**Статус: есть** (on-prem, нет телеметрии).
**План (P0):** проверка исходящих в attack-sim; в КП явный пункт.

### T-14. Обновления без интернета
**Сейчас:** pull образов с registry.
**План (P0):** `docs/offline-update.txt` — tarball образов + `docker load` + migrate + rollback. Скрипт `scripts/keeppam-upgrade.sh`.
**DoD:** стенд без default route обновляется с USB/ISO.

## 5. Функциональный блок (T-15 … T-51)

### T-15. Портал EN+RU, запрос доступа без пароля
**Сейчас:** портал RU; vault inject есть.
**План (P1, 4–6 нед.):**
- i18n: `web/src/i18n/{ru,en}.ts` + `react-i18next` (или свой словарь).
- Переключатель языка в шапке, cookie `kp_lang`.
- Все user-facing ошибки API — коды, UI переводит (не сырой русский с бэка).
**DoD:** полный сценарий JIT+replay на EN без «голых» русских строк в UI.

### T-16. Кворум согласующих (2 из 3, 3 из 5)
**Статус: есть** (sequential manager→security **и** quorum N-of-M, миграция `074`).
**Реализация:** `policy/quorum.go`, `requests.go`, карточка актива, заявки. Снимок N/M/группы на заявке. Один голос на актора; deny любым из пула; binding на N-м голосе.
**DoD:** демо 2 из 3: два разных согласующих → binding; третий не нужен; повтор того же — 409.


### T-17. Синхронизация паролей nix / AD / LDAP / Oracle / MSSQL / MySQL
**Сейчас:** ротация SSH, PostgreSQL, MySQL. Нет AD/Oracle/MSSQL sync «одна УЗ — много систем».
**План (P4):**
- Сущность `password_set` (логический пароль) + members (account_id на разных активах).
- Job: rotate master → push ко всем members (порядок: AD last или first — настройка).
- Коннекторы: уже есть SSH/PG/MySQL; добавить LDAP bind+unicodePwd; Oracle (thick client в worker); MSSQL (после T-33 TDS).
**DoD:** смена в KeepPAM меняет local unix + AD user в тесте.

### T-18. Ротация и JIT в многоузловом HA
**Зависит от T-06/T-07.**
**План (P3):** leader-election на rotation jobs (pg advisory lock или Redis). JIT binding в общей БД — уже ок.
**DoD:** kill worker во время rotate — job подхватывает другой узел, пароль не «завис» halfway (двухфазный: generate → set remote → commit vault).

### T-19. Восстановление после split-brain
**Сейчас:** нет.
**План (P5):** fencing (один writer PG); reconciliation: сравнить vault version vs last-success на цели; если drift — force rotate. Runbook в `docs/ha.txt`.
**DoD:** изоляция DC на 10 мин → restore → нет двух разных паролей в vault vs host.

### T-20. Динамические группы по имени/тегу/платформе/адресу
**Сейчас:** теги + policy overlay + nested tags/groups. Нет auto-membership по regex адреса.
**План (P1–P2, 2 нед.):**
- `dynamic_group_rules`: match name/tag/platform/hostname/cidr.
- Cron reconcile → group members.
- Policy на группу применяется автоматически (уже умеем).
**DoD:** новый актив `prod-db-01` с тегом `prod` попадает в группу без ручного bind.

### T-21. Авторотация по правилам
**Статус: есть** (rotation policies).
**План:** UI/доки — явно «правила: TTL, после checkout, после сессии». Регресс.

### T-22. Временной диапазон доступа
**Статус: есть** (JIT TTL, ABAC time window).
**План:** в acceptance — cron window «только пн–пт 09–18».

### T-23. «Четыре глаза» — супервайзер сессии
**Статус: есть** (миграция `075`, право `sessions.supervise`).
**Реализация:** флаг актива `require_supervisor` + опциональная группа; сессия `pending` до `supervisor_approved_at`; connect SSH/RDP/SQL/k8s/HTTPS блокируется; SSH-баннер wait; dual-control; break-glass skip; timeout 15 мин; kill супервайзером.
**DoD:** RDP/SSH не стартует без Authorize; после Approve — сессия идёт; deny/timeout закрывает; свою сессию супервизить нельзя.

### T-24. Break-glass
**Статус: есть.**
**План:** регресс notify (уже `docs/jit-notify.txt` / SMTP).

### T-25. AD-группа на время сессии + rotate после disconnect
**Сейчас:** нет.
**План (P4, 4–6 нед.):**
- На учёте/активе: `ad_privileged_group_dn`.
- Session start: LDAP add member; end/kill: remove + rotate password (T-17 коннектор).
- Идемпотентность и retry; если remove fail — critical audit + ticket.
**DoD:** user не в группе до сессии, в группе во время, не в группе после; пароль сменён.

### T-26. Прозрачный шлюз
**Статус: есть** (SSH :2222, HTML5 RDP).
**План:** не менять модель; native RDP — T-29.

### T-27. Контроль буфера / принтеров / дисков RDP
**Сейчас:** Guacamole; DLP скорее режет, чем «сохраняет все возможности».
**План (P4):** policy flags `rdp_clipboard`, `rdp_drive`, `rdp_printer` (default off). Включение — явное исключение DLP. Запись clipboard — T-31.
**DoD:** два профиля: DLP-strict (всё off) и full (clipboard on, файл в capture).

### T-28. Сессия без раскрытия пароля
**Статус: есть.**

### T-29. Любой клиент (PuTTY, Windows RDP, Royal TSX)
**Сейчас:** любой SSH-клиент на :2222; RDP — только браузер.
**План (P4/P5):** RDP gateway (RDG/HTTPS или TCP 3389 terminate → inject creds → target). Сложность высокая; конфликт с T-27 DLP.
**DoD SSH:** PuTTY/SecureCRT/Royal TSX — уже. DoD RDP: mstsc → KeepPAM → target без пароля в клиенте. Citrix — T-33.

### T-30. Шлюз: auth на gateway, затем целевая УЗ
**Статус: есть** (SSH menu / portal).

### T-31. Запись файлов SFTP/SCP/clipboard с восстановлением
**Сейчас:** DLP deny scp/sftp (`policy/dlp.go`). Записи файлов нет.
**План (P2, 4–6 нед.) — второй приоритет после T-16:**
- Policy: `file_transfer = deny | audit | capture`.
- SSH: проксировать subsystem sftp / scp sink в object store `recordings/files/{session_id}/`.
- RDP clipboard file: из guac stream, если включён clipboard.
- UI: список файлов сессии, download (RBAC `sessions.files.read`).
- WORM: тот же backend, что recordings (S3 lock).
**DoD:** `scp file user@keeppam:` → файл в UI, download байт-в-байт совпадает; deny-режим по-прежнему работает.

### T-32. Мониторинг: I/O + метаданные (процессы, окна, файлы)
**Сейчас:** stdin/stdout/keystroke/screen_text; процессы/окна Windows — нет (нужен агент или глубокий RDP).
**План (P2):**
- Имена файлов — из T-31 events `file_transfer`.
- Заголовки окон — эвристика OCR (T-10) + опционально RDP RAIL window titles если доступны в guac.
- Процессы — не обещать без агента; в КП: «из протокола, не с хоста».
**DoD:** forensic фильтр по имени файла; window title — best-effort OCR.

### T-33. Протоколы
| Протокол        | Сейчас        | Фаза | Подход |
|-----------------|---------------|------|--------|
| SSH + L/R fwd   | есть (+ network PAM) | — | регресс |
| RDP over TLS    | HTML5 guac    | P4 | native — T-29 |
| RemoteApp       | нет           | P4 | guac RemoteApp params |
| VNC / SSL       | есть          | — | |
| X11 over SSH    | частично (SSH) | P2 | не отдельный decoder |
| HTTP/HTTPS      | есть          | — | |
| SFTP/SCP        | deny only     | P2 | T-31 |
| Microsoft SQL   | PG/MySQL wire | P2/P4 | TDS proxy (порт 1433), login inject, query log |
| Telnet          | нет           | P5 | tty proxy, кодировки T-43 |
| TN3270          | нет           | P5 / SOW | отдельный decoder |
| Citrix ICA/CGP/STA | нет        | P5 / SOW | отдельный модуль, не guac |

**MSSQL (первый из «нет» в таблице):** worker `protocol=mssql`, pre-login/TLS, TDS login с vault password, запись SQL batch в session_events. Оценка 4–6 нед.

### T-34. Приложения RDS / Citrix
**RDS RemoteApp:** P4 вместе с T-33 RDP.
**Citrix:** P5 SOW.

### T-35. GSSAPI / Kerberos в SSH
**Сейчас:** нет (password/key/cert).
**План (P4/P5):** session-worker как Kerberos client (keytab PAM service) или constrained delegation. Сложный AD-контур.
**DoD:** `ssh -K` через KeepPAM на цель с SPN `host/asset`.

### T-36. Live view + kill, свой проигрыватель

**План (P2):** фильтры UI = чек-лист ТЗ; filename index; «архивные» сессии помечаются `archived=true`, поиск не требует монтирования SMB.

### T-38. Скорость воспроизведения

### T-39. Список команд без агента

### T-49. UEBA: нетипичное поведение, индекс риска

### T-50. Факторы UEBA: время, серверы, активности, динамика клавиш, мышь
**Сейчас:** время/серверы/spread. Клавиши/мышь — нет.
**План (P5):** inter-key interval из keystroke events; mouse — из guac motion (sampling). ML не обязателен — z-score vs baseline.
**DoD:** аномально быстрый ввод поднимает risk; notify — T-51.

### T-51. Уведомление при нетипичном поведении
**Сейчас:** notify на JIT/break-glass.
**План (P2–P5):** hook `ueba.anomaly` → SMTP/webhook (существующий notify service).
**DoD:** письмо при risk > порога на сессии.

## 9. Риски и сознательные исключения

| Риск | Решение |
|------|---------|
| Citrix ICA / TN3270 — годы у Fudo | SOW / OEM, не в критическом пути |
| Native RDP vs DLP | два профиля политики, default deny clipboard |
| «Без чужого ПО» vs guacd | bundled runtime + NOTICE, не форк с нуля |
| Метаданные процессов Windows без агента | не обещать; OCR/RAIL best-effort |
| Split-brain паролей | fencing PG + force-rotate, не multi-master vault |
| 3+2 как в T-52 | P5; в пилоте 2+2 (P3) с оговоркой в КП |

Не делать в этом плане: полное live OCR, NAC, eIDAS, shell AST (см. `docs/main21.txt`).
