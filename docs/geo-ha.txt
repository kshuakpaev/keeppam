# KeepPAM: SOW-GEO-HA — multi-site async geo

Сейчас в продукте: HA **внутри одного сайта** 2+2 / 3+2 (`docs/ha.txt`).
Этот SOW — **два (и более) ЦОД** с async PostgreSQL + политика fencing.

## Фазы

| Фаза | Содержание | Статус |
|------|------------|--------|
| **1** | Site identity, standby write-fence, lag probe, compose overlay, runbook | **есть** |
| **2** | Recordings sync (S3/rsync) + promote automation helpers | план |
| **3** | DNS/VIP cutover playbook + acceptance drill script | план |
| **4** | Split-brain fencing hardening / witness | план |

## Phase 1 — включение

```bash
# Site A (primary)
KEEPPAM_SITE_ID=site-a
KEEPPAM_SITE_ROLE=primary
KEEPPAM_SITE_PEER_URL=https://site-b.example/livez
KEEPPAM_SITE_REPLICA_DSN=postgres://…@site-b-pg:5432/keeppam   # optional lag view of B

# Site B (standby)
KEEPPAM_SITE_ID=site-b
KEEPPAM_SITE_ROLE=standby
KEEPPAM_SITE_REPLICA_DSN=postgres://keeppam:…@postgres:5432/keeppam  # local standby PG
KEEPPAM_SITE_MAX_LAG_SECONDS=120   # /readyz → 503 if lag exceeds
```

Compose sketch (site B reads from A):

```bash
cd deploy
# Site A: обычный HA
docker compose -f docker-compose.yml -f compose.ha.yml up -d

# Site B: overlay geo (PG streaming replica + API standby)
docker compose -f docker-compose.yml -f compose.geo-standby.yml up -d
```

## API

- `GET /api/v1/admin/geo/status` (`compliance.read`) — role, lag, allows_writes
- `/readyz` — на standby с `MAX_LAG` падает при отставании реплики

## Fencing

При `SITE_ROLE=standby`:

- `POST` создание сессии → **503**
- SSH gateway не принимает новые коннекты
- Login/admin read-only сценарии допустимы (метаданные с replica)

## Promote (ручной, фаза 1)

1. Убедиться, что site A down / planned cutover.
2. Promote PG standby (`pg_ctl promote` / Patroni).
3. `KEEPPAM_SITE_ROLE=primary` + restart API/workers на B.
4. Переключить DNS/VIP на edge B.
5. Smoke: login, JIT, SSH session (`docs/dr-runbook.txt`).

## Acceptance (цель SOW)

Kill site A → login/JIT на site B в согласованном SLA (после promote).

## Out of scope phase 1

Автоматический Patroni/Keepalived VIP между ЦОД; bi-directional active-active writes.
