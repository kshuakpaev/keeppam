# KeepPAM: JIT согласование

На карточке актива — режим согласования. Снимок пишется в заявку при создании (смена настройки актива не ломает уже открытый запрос).

Один человек не одобряет свою заявку. Повторный голос того же актора — отказ. Deny отклоняет заявку целиком.

Миграции: `045` (этапы), `074` (кворум).

## Sequential (default)

Один этап `manager` — любой с `access.approve`.

PROD / чувствительные активы: **Руководитель + ИБ**.

```
Request
  → Manager (access.approve)
  → Security (access.approve.security)
  → JIT binding
```

Один человек не закрывает два этапа. Deny — на текущем этапе, своим правом. Роль `security` для второго этапа.

## Quorum N из M (main22 T-16)

Примеры: 2 из 3, 3 из 5. Голоса параллельные, не этапы.

```
Request
  → голос 1 … голос N из группы согласующих
  → JIT binding
```

На карточке: режим «Кворум», N, M (1 ≤ N ≤ M ≤ 16), опционально PAM-группа. Если группа не задана — голосует любой с `access.approve`. Член потомка группы считается членом родителя (как ACL).

Любой из пула может отклонить заявку до набора кворума. После N голосов создаётся binding; лишний голос не нужен.

Audit: `access.request.quorum_vote` на каждый голос, `access.request.approved` при достижении N.
