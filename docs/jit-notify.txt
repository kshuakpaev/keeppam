# KeepPAM: JIT-уведомления

In-app inbox + опциональный webhook + SMTP на заявки доступа.

## Inbox

Любой залогиненный пользователь видит **свои** уведомления.

| Событие | Кому |
|---------|------|
| JIT create | все с правом текущего этапа (`access.approve` для manager), кроме requester |
| JIT stage | все с правом **следующего** этапа, кроме requester и тех, кто уже согласовал |
| JIT approve/deny | requester (только финальный approve/deny, не промежуточный этап) |
| Dual-control checkout create | все с `assets.write`, кроме requester |
| Checkout approve/deny | requester |
| Сессия ждёт супервайзера | все с `sessions.supervise` (или члены группы супервайзеров), кроме оператора |
| Supervisor approve/deny | оператор сессии |

Cancel / expire — без уведомлений.

API (session + CSRF, без отдельного perm):

- `GET /api/v1/notifications?limit=50` → `{notifications, unread}`
- `GET /api/v1/notifications/unread-count`
- `POST /api/v1/notifications/{id}/read`
- `POST /api/v1/notifications/read-all`

UI: колокольчик в sidebar, poll 25s, клик → `/access-requests`.

## Webhook

Конфиг → **Уведомления** (`settings.write`).

| Поле | Смысл |
|------|--------|
| `enabled` | мастер-выключатель webhook |
| `webhook_url` | HTTPS POST JSON |
| `auth_header` | write-only, шифруется (`Authorization` или `Header: value`) |
| `timeout_sec` | 1–30, default 5 |

Только `jit.created` / `jit.stage` / `jit.approved` / `jit.denied`. Checkout в webhook не уходит.

Ошибка доставки **не** блокирует approve. Аудит `notify.webhook.failed`, `last_error` в UI.

Payload (без секретов):

```json
{
  "source": "keeppam",
  "event": "jit.created",
  "id": "…",
  "asset_id": "…",
  "asset_name": "prod-db",
  "requester_id": "…",
  "requester_username": "alice",
  "duration_minutes": 60,
  "reason": "…",
  "ticket_id": "INC-1",
  "status": "pending",
  "approver_id": null,
  "ts": "2026-08-13T15:00:00Z"
}
```

User-Agent: `KeepPAM-Notify/1.0`.

## SMTP

Те же события, что inbox (JIT **и** checkout). Письмо на `users.email`.

Пропускаются пустые адреса и заглушки `@ldap.local` / `@oidc.local` / `@saml.local`.

| Поле | Смысл |
|------|--------|
| `smtp_enabled` | выключатель почты |
| `smtp_host` / `smtp_port` | default port 587 |
| `smtp_tls` | `starttls` (587) / `tls` (465) / `none` (локальный relay) |
| `smtp_tls_insecure` | не проверять сертификат |
| `smtp_from` | From, обязателен при enabled |
| `smtp_username` / `smtp_password` | AUTH PLAIN; пароль write-only, шифруется |
| `timeout_sec` | общий с webhook, для SMTP минимум 15s |

`POST /api/v1/admin/settings/notify/test-email` — письмо на email текущего админа.

Ошибка SMTP не блокирует approve. Аудит `notify.smtp.failed`, `smtp_last_error` в UI.

Тема = заголовок inbox, тело = текст inbox, UTF-8, без секретов.
