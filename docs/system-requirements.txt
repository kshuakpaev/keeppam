# KeepPAM: системные требования к установке

Документ для планирования железа и ВМ под compose-дистрибутив (`docs/install.txt`) и Virtual Appliance (`docs/appliance-ova.txt`).

Три профиля:

| Профиль | Назначение |
|---------|------------|
| **Минимальный** | Лаб, PoC, демо, до ~10 одновременных сессий |
| **Оптимальный** | Боевой пилот / продакшен средней нагрузки |
| **Расширенный** | HA, наблюдаемость (SET=full), высокая конкуренция, долгие RDP/записи |

Цифры — **на один хост**, где крутится Docker Compose (все сервисы вместе), если не указано иное. Для HA 2+2 / 3+2 ресурсы **на каждый** control/worker узел — см. раздел «Масштабирование».

---

## 1. Программные требования (все профили)

| Компонент | Минимум |
|-----------|---------|
| ОС | Linux x86_64 (RHEL/Rocky/Alma 8+, Ubuntu 22.04/24.04 LTS) |
| Docker Engine | 24+ |
| Docker Compose | plugin v2 (`docker compose`) |
| Ядро | cgroup v2 желателен; `IPC_LOCK` / memlock для api и session-worker (`docs/memory.txt`) |
| Сеть | исходящий registry **не нужен** при offline-бандле (`docs/offline-update.txt`) |
| Браузер админа | актуальный Chrome / Edge / Firefox |

Дополнительно по сценарию:

- TLS/mTLS, KMS, S3/WORM — `docs/prod-infra.txt`
- HA — `docs/ha.txt`
- Запись сессий на NFS/SMB/S3 — `docs/archive-smb-nfs.txt`, `docs/prod-infra.txt`

---

## 2. Минимальный профиль (лаб / PoC)

**Состав:** `SET=core` — API, session-worker, web, Postgres, Redis, guacd, guacenc (по необходимости).

| Ресурс | Значение |
|--------|----------|
| vCPU | **4** |
| RAM | **8 GiB** |
| Диск (SSD) | **80 GiB** свободно под ОС + Docker + volumes |
| Сеть | 1 Gbit/s к целевым активам и к пользователям |
| Одновременные сессии | до **~10** (SSH + несколько RDP) |
| Активы в каталоге | безлимит при SKU users; UI — поиск и страницы по 50 (max 200), см. docs/license.txt |

Запас на диске:

- образы Docker core ≈ 5–8 GiB;
- Postgres + Redis — единицы GiB на старте;
- записи сессий (`recordings`) — **отдельно планировать** (RDP сильно тяжелее SSH).

Совпадает с рекомендацией для Virtual Appliance: CPU ≥4, RAM ≥8 GiB, диск ≥80 GiB (`docs/appliance-ova.txt`).

**Не подходит** для: постоянного HA, OpenSearch/Grafana на том же хосте, десятков параллельных RDP с записью.

---

## 3. Оптимальный профиль (пилот / продакшен)

**Состав:** `SET=core` + внешний или локальный бэкап; TLS; по возможности вынести recordings на отдельный том/S3.

| Ресурс | Значение |
|--------|----------|
| vCPU | **8** |
| RAM | **16 GiB** |
| Диск (SSD/NVMe) | **250 GiB** система + Docker |
| Том recordings | **500 GiB+** (или S3/NFS, см. ниже) |
| Сеть | 1–10 Gbit/s; задержка до активов по возможности &lt; 50 ms |
| Одновременные сессии | **~50** смешанных (ориентир) |
| Пользователи PAM | сотни учёток / десятки одновременных операторов |

Рекомендации:

- отдельный volume или диск под `recordings` и Postgres data;
- ежедневный бэкап БД (`scripts/backup.sh`);
- `KEEPPAM_COOKIE_SECURE=true` при HTTPS;
- мониторинг хоста (CPU, RAM, disk, inode) даже без профиля `obs`.

---

## 4. Расширенный профиль (HA + нагрузка + observability)

**Состав:** `SET=full` и/или `KEEPPAM_HA=1|3`, OpenSearch, Grafana, Tempo, Prometheus; при необходимости отдельные ноды под worker и БД.

| Ресурс (на control-ноду «всё в одном») | Значение |
|----------------------------------------|----------|
| vCPU | **16+** |
| RAM | **32–64 GiB** |
| Диск ОС/Docker | **500 GiB** NVMe |
| Recordings / архив | **1 TiB+** или object storage (S3) с Object Lock |
| Одновременные сессии | **100+** (нужен HA workers) |
| Наблюдаемость | профиль `obs` / SET=full на выделенных ресурсах |

Типичное разнесение (расширенный продакшен):

| Роль | Ресурсы (ориентир на узел) |
|------|----------------------------|
| Control API (2–3 шт.) | 4–8 vCPU, 8–16 GiB |
| Session-worker (2+ шт.) | 4–8 vCPU, 8–16 GiB (RDP/guacd рядом или sidecar) |
| Postgres (+ replica) | 4–8 vCPU, 16–32 GiB, быстрый SSD |
| Redis | 2 vCPU, 4–8 GiB |
| OpenSearch (если SET=full) | 4+ vCPU, 16+ GiB **на узел** (heap ≈½ RAM) |
| Grafana / Prometheus / Tempo | 2–4 vCPU, 8 GiB суммарно или отдельный стенд |

HA 2+2 / 3+2: см. `docs/ha.txt`. Одна Virtual Appliance **не** заменяет полноценный HA.

## 4a. Профиль NIT п. 4 (1000 сессий / 200 операторов)

Не лаб-compose. Helm: `values-nit-p4.yaml` (6 API, 20 worker, 8 guacd). Compose: `compose.scale.yml` + `--scale`. Плотность и микс — `docs/nit-p4.txt`. Железо с запасом 30% — `docs/nit-bom.txt`.

| | NIT p.4 |
|--|---------|
| session-worker | 20 × 4–8 vCPU / 8–16 GiB |
| guacd | 8 |
| API | 6 |
| Одновременные сессии | **1000** (SSH-heavy 80/15/5) |
| Операторы портала | **200+** (Redis-сессии, без cap учёток) |

## 5. Оценка по типу сессий (диск и CPU)

| Тип | Нагрузка на CPU/RAM worker | Запись на диск (порядок) |
|-----|----------------------------|---------------------------|
| SSH (текст) | низкая | единицы–десятки МБ/час |
| RDP/VNC HTML5 (guacd) | высокая | **сотни МБ – несколько ГБ/час** при полной записи |
| БД wire (PG/MySQL/MSSQL) | средняя | JSONL — умеренно |
| kubectl / HTTPS proxy | средняя | зависит от трафика |

Правило планирования recordings:  
`ёмкость ≈ средняя_длительность × число_параллельных_RDP × МБ/час × срок_хранения`.

При WORM/S3 локальный диск можно уменьшить, оставив буфер под активные сессии.

## 6. Сеть и порты (типовой single-host)

Исходящие к активам: SSH 22, RDP 3389, VNC 5900, БД, HTTPS — по каталогу.

Входящие к KeepPAM (по умолчанию compose):

| Порт | Сервис |
|------|--------|
| 5173 | Web UI |
| 8080 | API |
| 2222 | SSH gateway (session-worker) |
| 2121 | FTP gateway (session-worker) |
| 2323 | Telnet gateway (session-worker) |
| 9090+ | только при obs (Prometheus и др.) |

Между нодами HA — внутренняя сеть Docker/K8s; наружу обычно VIP/LB на UI/API/SSH.

## 8. Опция ИИ-copilot (SOW-AI-COPILOT)

Не входит в базовый `SET=core`. Включается overlay `deploy/compose.ai.yml` / Helm `ai.enabled` и лицензией `ai_copilot`.

| Режим | Ресурсы |
|-------|---------|
| **mock://local** (стенд, CI) | +0 GPU; worker делит RAM API; сводки без модели |
| **Ollama on-prem (Llama 3.2 / Qwen 2.5 / Mistral / Gemma 2 / Phi-3)** | контейнер `ai-runtime`, веса по кнопке «Скачать в Ollama»; 3B CPU-friendly, 7–9B ≈ +8–16 GiB RAM |
| **Веса моделей offline** | `dist/keeppam-ai-models-*.tar`; install не ходит в интернет |

ИИ **не** в live deny / JEA / SSH PTY. Подробности: `docs/ai-plan.txt`.
