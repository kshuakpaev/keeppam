# KeepPAM: Adaptive MFA (step-up)

Повторный фактор, если риск выше порога ACL/Policy. Это не логин-MFA: пользователь уже в KeepPAM.

## Connect

ACL или именованная Policy: `max_risk` > 0 и `risk_action=require_mfa`.

Если score > `max_risk` на connect (HTTP-сессия, app/k8s lease, SSH `:2222`):

1. API отвечает `403` `{ code: "mfa_required", challenge_token, totp, webauthn, risk_score, max_risk, risk_factors }`.
2. UI: TOTP и/или Passkey.
3. `POST /api/v1/auth/stepup/totp` или `.../stepup/webauthn/begin|finish` → `{ step_up_token }` (TTL 2 мин, привязан к user+asset).
4. Повтор connect с `step_up_token`.

Нет ни TOTP, ни passkey → `403` `mfa_not_enrolled`.

SSH-шлюз: интерактивный TOTP в канале (WebAuthn на `:2222` нет).

## Операции внутри сессии

Тот же `require_mfa`, но score = connect-факторы + баллы операции (`docs/command-risk.txt`).

| Канал | Поведение |
|-------|-----------|
| HTTPS reverse-proxy | держит запрос до 60 с; диалог в рамке сессии; грант на сессию 30 мин |
| Web SQL | WS `mfa_required` + диалог; повтор statement |
| kubectl UI / cookie API | `403` `mfa_required` + диалог; повтор вызова |
| kubectl `:16443` | держит до 60 с, пока MFA в KeepPAM; затем тот же запрос проходит |
| Native SQL wire | deny + текст «confirm MFA in web SQL console» (диалога нет) |
| SSH PTY | **deny** (интерактива на команду нет) |

Грант Redis `stepup-op:{session}` после успешного MFA. Повторные опасные операции в этой сессии не спрашивают фактор снова, пока грант жив.

`GET /api/v1/admin/sessions/{id}/op-stepup` — pending challenge для UI (poll).

JIT по-прежнему можно создать (как при `require_approval`). Break-glass и admin bypass (`users.write`) шаг пропускают.

## API

| Метод | Путь | Право |
|-------|------|--------|
| POST | `/api/v1/auth/stepup/totp` | сессия |
| POST | `/api/v1/auth/stepup/webauthn/begin` | сессия |
| POST | `/api/v1/auth/stepup/webauthn/finish` | сессия |
| GET | `/api/v1/admin/sessions/{id}/op-stepup` | `sessions.connect` |

Connect: `step_up_token` в теле `POST /admin/sessions`, `/assets/{id}/app/access`, `/assets/{id}/k8s/access`.

Миграция `051`: CHECK `risk_action` включает `require_mfa`. Seed Policy `adaptive-mfa` (порог 40, не привязана).
Миграция `113`: CHECK расширен до `terminate` / `lock_account` (`docs/ueba.txt`).

## Аудит

`access.stepup.challenged` / `access.stepup.ok` / `access.stepup.failure`. Оценка по-прежнему `access.risk.evaluated` (`decision=require_mfa`, `phase=operation` для in-session).

## Вне scope

WebAuthn на SSH-gateway. Remember-device. Step-up на каждую SSH-команду в PTY.
