2.	Описание и требуемые функциональные, технические, качественные и эксплуатационные характеристики

Услуга по предоставлению системы контроля привилегированных пользователей Privileged Access Management (далее - система)
Система должна быть реализована в виде решения от одного производителя и поставляться в виде готовых программных комплексов (Virtual Appliance).
	Система должна иметь поддержку платформ виртуализации VMware и Hyper-V актуальных (поддерживаемых производителем) версий.
	Стандартная функциональность Системы должна обеспечиваться без использования решений других производителей ПО.
	Система не должна требовать установки агентов на рабочие станции привилегированных пользователей и целевые системы для функционирования каких-либо ее компонентов.
	Система должна работать напрямую с трафиком пользовательской сессии, без использования эмуляции или граббинга экрана.
	В состав Системы должны входить модули по управлению доступом и управлению сессиями привилегированных пользователей. Система должна иметь возможность расширения/масштабирования отдельно для каждого из модулей. Добавление дополнительных модулей (узлов) должно осуществляться без остановки функционирования Системы.
	Система должна поддерживать отказоустойчивую конфигурацию (кластер) с возможностью разнесения модулей по нескольким площадкам.
	Система должна быть интегрирована в доменную инфраструктуру Заказчика и иметь способы интеграции с глобальными каталогами.
	В Системе должен быть реализован механизм автоматического обнаружения неконтролируемых привилегированных учетных записей.
	Система должна иметь встроенный движок OCR для распознавания текста в графических сессиях.
	Система должна поддерживать интеграцию со средствами многофакторной аутентификации.
	Система должна обеспечивать ведение журнала и возможности аудита всех действий, производимых пользователями и администраторами в ней.
	Во время штатной работы Система не должна требовать удаленного подключения со стороны ее производителя. 
	Обновления компонентов Системы должны осуществляться без необходимости подключения к сети интернет.

Функциональные (технические) требования: 

	Система должна иметь веб-портал (на английском и русском языках), через который привилегированные пользователи будут запрашивать предоставление доступа к целевой системе без раскрытия пароля. 
	В Системе должен быть реализован механизм согласования с возможностью создания кворума согласующих (например, 2 из 3 и 3 из 5).
	Система должна иметь механизм обеспечения синхронизации паролей между учетными записями различных типов (локальных аккаунтов *nix систем, доменных УЗ Active Directory, LDAP, Баз данных Oracle, MSSQL, MySQL и т.д.).
	Система должна осуществлять автоматизацию смены паролей учетных записей и процессов запроса и согласования привилегированного доступа в многоузловом отказоустойчивом режиме, допускающем отказ одного из узлов без потери производительности и работоспособности.
	При нарушении и последующем восстановлении сетевой связанности между узлами, Система должна обеспечивать полностью автоматическое восстановление процессов смены паролей учетных записей и процессов запроса и согласования привилегированного доступа к целевым аккаунтам.
	Система должна иметь механизмы создания динамических групп целевых учетных записей и целевых систем по ряду параметров (имя, описание, платформа, тэг, доменное имя, сетевой адрес и т.д.) с возможностью комбинации этих параметров и автоматического применения правил доступа к обнаруженным целевым системам и целевым учётным записям.
	Система должна обладать возможностью менять пароли привилегированных учетных записей в автоматическом режиме по заранее заданным правилам.
	Система должна иметь возможность разграничивать доступ привилегированных пользователей к целевым системам на основании определенного временного диапазона.
	Система должна иметь возможность использования подхода «четырех глаз», который позволяет предоставлять доступ к конкретной сессии только при наличии назначенного пользователя (супервайзера) и авторизации им этой сессии.
	Система должна иметь возможности предоставления аварийного доступа к целевым учетным записям с пропуском процедуры согласования и игнорирования временных интервалов разрешенного запроса доступа с оповещением ответственных сотрудников о каждом факте такого аварийного доступа.
	Система должна иметь возможность предоставлять необходимые полномочия пользователя только при запросе сессии путем помещения его учетной записи в соответствующую привилегированную группу Microsoft Active Directory (AD). По окончании или принудительном разрыве сессии Система должна удалить пользователя из привилегированной группы AD и сменить пароль.
	Сессии удаленной работы сотрудников с защищаемыми целевыми системами должны на сетевом уровне и прозрачно для конечного пользователя проходить через Систему. 
	При проксировании сессий должны сохраняться все возможности контроля протокола (буфер обмена, пробрасываемые принтеры, локальные диски рабочих станций и т.д.).
	Должен быть возможен сценарий открытия сессии к целевой системе без раскрытия пароля конечного привилегированного аккаунта. 
	Должна существовать возможность открытия сессии к целевой системе через любое клиентское приложение (Putty, Kitty, SecureCRT, Windows RDP client, Royal TSX на MacOS и т.д.).
	Должна присутствовать функциональность шлюза безопасности, при которой происходит аутентификация пользователя на шлюзе и его дальнейший переход к конечной привилегированной учетной записи без ввода пароля целевого аккаунта. 
	Система должна позволять записывать файлы, передаваемые через SFTP, SCP или буфер обмена в RDP подключениях с возможностью восстановления их в исходном виде. 
	Должны обеспечиваться мониторинг и регистрация действий пользователей при совершении ими манипуляций на целевых системах:
-	поток пользовательского ввода/вывода;
-	метаданные (учетная запись пользователя, временные метки, запускаемые процессы, заголовки открываемых окон, имена передаваемых файлов). 
	Система должна обеспечить автоматическое распознавание в проходящем сетевом трафике и запись сессий пользователей, устанавливаемых по следующим протоколам:
-	Citrix ICA (в т.ч. инкапсулированный в CGP) включая поддержку записи последних серверных версий Citrix – XenApp 6.5, XenDesktop 7.0, 7.6 и 7.15, SOCKS proxy и Citrix STA;
-	RDP (в т.ч. over TLS) версий 4,5,6,7,8,8.1, в т.ч. Remote Desktop Services (RemoteApp);
-	X11 (over SSH);
-	VNC (в т.ч. over SSL);
-	SSH, в том числе контроль и запись трафика Local и Remote Port Forwarding;
-	Telnet, TN3270;
-	SFTP (SCP);
-	HTTP и HTTPS;
-	Microsoft SQL Server версии 2014 и выше.
	Система должна обеспечить возможность контроля и мониторинга приложений, публикуемых посредством терминальных служб Microsoft RDS и/или Citrix.
	Система должна обеспечить поддержку GSSAPI и Kerberos в SSH сессиях.
	Система должна предоставлять возможность просмотра активной сессии в режиме реального времени с возможностью ее прерывания. Просмотр активной сессии должен производиться с помощью проприетарного защищенного проигрывателя. 
	Система должна обеспечить просмотр завершенной сессии с возможностью текстового поиска, также вести сквозной поиск одновременно по всему объему записанных сессий, включая расположенные в архиве, а также иметь возможность задания множества поисковых критериев одновременно:
-	время начала и завершения сессии;
-	IP-адрес (подсеть) пользователя;
-	IP-адрес (подсеть) сервера, с которым была установлена сессия;
-	протокол (список протоколов), по которому была установлена сессия;
-	часть слова или фраза в потоке пользовательского ввода/вывода (должен быть реализован полнотекстовый поиск по потоку пользовательского ввода/вывода);
-	метаданным (учетная запись пользователя, временные метки, запускаемые процессы, заголовки открываемых окон, имена передаваемых файлов);
-	часть имени файла, переданного во время сессии.
	Должна быть возможность ускорять и замедлять скорость воспроизведения записи.
	Запись сессии должна включать полный список команд, выполненных пользователем во время записи, и не должна требовать установки агентского программного обеспечения. 
	Запись сессий должна осуществляться из потока ввода/вывода (upstream/downstream) без потери качества и требовать минимальный объем на системе хранения. Прямая запись в формате видеофайлов или снимков экрана не допускается.
	Должна присутствовать возможность экспорта записанной сессии в файл для воспроизведения ее как видео.
	Система должна обеспечить возможность уполномоченному оператору разорвать любую активную (незавершенную) сессию. Также должна быть реализована возможность автоматического разрыва сессии при нарушении политики безопасности (в том числе на основе черных и белых списков команд/заголовков окон). Система должна иметь возможность массовой загрузки черных и белых списков.
	Записанные сессии должны содержать следующую информацию:
-	перехваченный сетевой трафик поддерживаемого протокола;
-	текст, введенный пользователем и отображенный пользователю (поток пользовательского ввода/вывода); должны поддерживаться распространенные кодировки символов русского языка, в том числе: CP1251, KOI8-R, UTF-8;
-	общая информация о сессии (метаданные), в том числе: время начала и завершения сессии, имена переданных во время сессии файлов, разрешенные и запрещенные подканалы протоколов от пользователя к серверу, список выполненных команд в гипертекстовых протоколах. 
	Система должна обеспечить возможность сохранить переданные во время сессии SFTP, SCP или RDP файлы (в том числе бинарные) в оригинальном виде, с возможностью восстановления в случае удаления.
	Система должна обеспечить поддержку хранения записанных сессий с защитой от несанкционированного доступа.
	Система должна обеспечить возможность организации автоматической архивации файлов с записанными сессиями в сетевое хранилище Заказчика по протоколам SMB/CIFS версии 2, 3, 4, а также по сетевому протоколу NFS.
	Система должна иметь возможность разграничения доступа администраторов с возможностью ограничения доступа к потоку пользовательского ввода, на просмотр завершенных и активных сессий пользователей. Подключение стороннего администратора для перехвата управления в сессия не допускается.
	Система должна иметь механизмы централизованной аутентификации администраторов для доступа к веб-консоли с помощью Microsoft AD, протокола Radius или сертификатов x509.
	Система должна иметь функционал выявления нетипичного поведения пользователей при работе под привилегированными учетными записями и формирования индивидуальных индексов риска для таких пользователей.
	При выявлении нетипичного поведения пользователей должны учитываться отклонения по времени входа, диапазону серверов и приложений, аномалии по набору производимых активностей, динамике нажатия клавиш при вводе информации, а также движения мыши. 
	Система должна иметь функционал уведомления заинтересованных лиц в случае выявления нетипичного поведения пользователей в сессии.

Требования к Система и технической поддержке:
	Лицензия на использование программного обеспечения Системы должны обеспечивать возможность работы неограниченного количества пользователей с не менее чем 100 информационными системами в отказоустойчивом режиме (не менее 3 модулей управления доступом и не менее 2 модулей управлению сессиями).
	Лицензия должна включать в себя возможность создания кластера.
	Система должна быть обеспечена технической поддержкой производителя не менее 12 месяцев.
