# Password sync AD ↔ local ↔ DB (КП-2.3 / T-17)

Логический набор `password_set` связывает несколько vault-учёток (разные активы).
Один rotate генерирует **один** пароль и пушит его на всех members через уже существующие коннекторы.

## Коннекторы remote rotate

| Цель | Как |
|------|-----|
| SSH / RDP-mgmt | `passwd` / Windows net user |
| PostgreSQL | `ALTER USER … PASSWORD` |
| MySQL | через SSH `mysql` |
| MSSQL | `ALTER LOGIN` (новый в этом срезе) |
| Oracle | `ALTER USER` thin (go-ora) или SQL*Plus через SSH :22 |
| AD/LDAP | `unicodePwd` / `userPassword` если у учётки `ad_user_dn` или у актива `ad_privileged_group_dn` |

Oracle wire SQL*Net — вне среза; см. `docs/oracle-pwdsync.txt`.

## Настройка

1. UI **Password sync** (`/password-sets`) или API `/api/v1/admin/password-sets`.
2. Создать набор, выбрать password-учётки (unix + AD + DB и т.д.).
3. **Sync order:**
   - `directory_last` (default) — сначала host/DB, потом AD
   - `directory_first` — сначала AD, потом host/DB
4. Кнопка **Rotate all** или rotate одной учётки из набора — peers получают тот же секрет автоматически.

Учётка может быть только в одном наборе.

## API

- `GET/POST /api/v1/admin/password-sets`
- `GET/PATCH/DELETE /api/v1/admin/password-sets/{id}`
- `POST /api/v1/admin/password-sets/{id}/rotate` — body `{ "apply_remote": true }`

## Миграция

`082_password_sync.sql` — `password_sets`, `password_set_members`.

## DoD

Смена в KeepPAM меняет local unix + AD user (и при необходимости DB/MSSQL) одним rotate набора.
