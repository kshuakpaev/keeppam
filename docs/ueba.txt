# KeepPAM: UEBA

Не ML. PAM смотрит **куда ходил пользователь** и **как быстро печатал / двигал мышь** (RDP/VNC guac) и поднимает риск / шлёт notify.

## Активы (connect)

Окно baseline — **30 дней**. Сессии `pending` / `active` / `ended`.

| Условие | Фактор | Баллы |
|---------|--------|-------|
| ≥3 разных актива в baseline и текущий актив **не** в этом наборе | `ueba_new_asset` | 25 |
| за 24ч уникальных активов ≥6 и ≥2× размера 30-дневного набора | `ueba_spread` | 20 |
| ≥3 разных исходных IP и текущий host **не** в наборе | `ueba_new_ip` | 20 |
| ≥3 разных подсети (/24 IPv4, /64 IPv6) и текущая **не** в наборе | `ueba_new_subnet` | 25 |

Холодный старт (0–2 актива / IP / подсети) — факторы не ставятся. Подсеть сильнее host: оба сразу не ставятся. Срабатывание в connect-score (`docs/abac-breakglass.txt`).

## Клавиши (post-session, T-50)

После индекса `.guac` (`recording-include-keys`): inter-key interval (IKI) между press, 15–3000 ms.

| | |
|--|--|
| Минимум клавиш | 20 |
| Baseline | median IKI прошлых сессий user за 30д (`ueba` / `keystroke_stats`) |
| Аномалия | z-score ≤ −2 vs baseline (≥3 прошлых) **или** cold-start median ≤ 55 ms |
| Фактор | `ueba_keystroke_fast` (+30 к `sessions.risk_score`) |

## Мышь (post-session, T-50)

Те же `.guac`: opcode `mouse` + `sync` → скорость движения (px/ms) между сэмплами с Δ≥8px, dt 5–2000 ms.

| | |
|--|--|
| Минимум | 40 moves / 20 velocity samples |
| Baseline | median velocity прошлых сессий (`ueba` / `mouse_stats`) |
| Аномалия | z-score ≥ +2 vs baseline **или** cold-start median ≥ 1.2 px/ms |
| Фактор | `ueba_mouse_fast` (+25) |

События: `ueba` (stats + anomaly), `risk` (anomaly). Notify — T-51 (`OnUEBAAnomaly`).

## Notify (T-51)

`notify.OnUEBAAnomaly` → inbox + SMTP + webhook `ueba.anomaly` (получатели `audit.read`).

## Аналитика

`GET .../analytics/overview` → anomaly `ueba_keystroke_fast` / `ueba_mouse_fast`. Карточка **Аналитика**.

## Авто-реакция (NIT §9)

На ACL / Policy: `max_risk` > 0 и `risk_action`:

| `risk_action` | Когда score > max_risk |
|---------------|------------------------|
| `deny` | отказ connect / операции |
| `require_approval` | JIT (connect) или hold команды (SSH) |
| `require_mfa` | step-up TOTP/Passkey |
| `terminate` | kill текущей сессии (`LiveHub` + `MarkEnded`) |
| `lock_account` | `users.status=locked`, `locked_until` +24ч, kill всех pending/active сессий пользователя |

Default из коробки — `deny`. Политику terminate/lock нужно включить явно. Блокировка единственного admin не защищена отдельно — как у brute-force lockout.

Аудит: `user.locked` reason=`ueba_risk`; `session.ended` via=`ueba_risk`.

## Вне scope (базовый UEBA)

Peer-group / ML / live mid-session — модуль **SOW-UEBA-ML** (`docs/ueba-ml.txt`). Полный классификатор поведения.
