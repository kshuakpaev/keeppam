# KeepPAM: Command Risk Engine

Парсер командной строки → класс риска → ALLOW / DENY / APPROVAL. Не заменяет glob JEA: pack по-прежнему режет набор команд, движок добавляет баллы и решение поверх ACL `max_risk`.

## Парсер

`ParseCommand` снимает обёртки (до 6 слоёв):

- `sudo` / `doas` / `pkexec` (+ флаги `-u user`, `--`)
- `su` / `su -c '…'` / `su user -c …`
- `nohup` / `nice` / `time` / `stdbuf` / `env` / `FOO=bar cmd`
- `sudo -i` / `su -` → `priv_shell` (класс `ssh.priv`)

JEA `MatchCommand` сравнивает паттерны с raw, inner и binary: `sudo ls` проходит allowlist `ls`.

DLP `scp`/`sftp`/`rsync` тоже через парсер (`sudo scp` по-прежнему deny).

## Баллы операции

Складываются с connect-факторами (`docs/abac-breakglass.txt`), cap 100. Сравнение с `max_risk` ACL/Policy.

| Класс | Примеры | Баллы |
|-------|---------|-------|
| *(пусто)* | `ls`, `cat`, `grep` | 0 — не перепроверяется |
| `ssh.status` | `systemctl status`, `journalctl` | 5 |
| `ssh.restart` | `systemctl restart/stop`, `kill` | 10 |
| `ssh.priv` | `sudo -i`, `su -` | 30 |
| `ssh.chmod` | `chmod` / `chown` | 40 |
| `ssh.chmod777` | `chmod 777` | 50 |
| `ssh.user` | `useradd`, `passwd`, `visudo` | 60 |
| `ssh.firewall` | `iptables`, `nft` | 70 |
| `ssh.destructive` | `rm`, `dd`, `mkfs`, `reboot` | 90 |
| `sql.drop` | `DROP DATABASE` / `DROP SCHEMA` | 100 |

## Решение в сессии

Line-buffer (QuietEcho) **всегда** на SSH PTY: DLP, JEA pack, live deny, risk.

| Режим | Когда |
|-------|--------|
| **Live deny** | `max_risk=0`, нет bypass: `ssh.destructive`, `ssh.firewall`, `ssh.user`, `ssh.chmod777` — **DENY до хоста**, событие `command_denied` kind `live_deny`, audit `session.command.live_denied`. Цепочки `\|`, `&&`, `;` — проверка каждого сегмента (не полный AST). `bash -c` / `sh -c` — unwrap как `su -c`. |
| **Risk / JEA** | Как раньше при `max_risk > 0` или command pack |

Без пакета и при `max_risk=0` low-risk (`ls`, `systemctl status`) проходят; destructive/firewall/user/chmod777 режутся live deny.

| `risk_action` | Если score > max_risk |
|---------------|------------------------|
| `deny` | DENY, событие `risk` |
| `require_mfa` | SSH PTY: DENY. HTTP/SQL/kubectl: step-up MFA (`docs/adaptive-mfa.txt`) |
| `require_approval` | PTY **ждёт** до 60 с: команда не уходит на хост, пока кто-то с `access.approve` (не заявитель) не одобрит. Таймаут/deny — команда не выполняется. Очередь: Запросы доступа → «Операции в сессии», канал `ssh`. |
| `terminate` | DENY + kill этой сессии |
| `lock_account` | DENY + lock УЗ 24ч + kill всех сессий пользователя |

Break-glass и admin bypass — wait пропускается, команда выполняется. Аудит: `session.command.approval_required` / `approved` / `denied` / `approval_timeout`. События сессии: `command_approval` / `command_approved` / `command_denied`.

Порог `max_risk` внутри сессии — из снимка connect (`docs/access-policy.txt`), не из live Policy.

## API / UI

`POST /api/v1/admin/jea/command-preview` (`jea.read`): `{ command, pack_id? }` → parsed + JEA + points.

JEA → SSH → «Проверить команду». Сессии → События и replay индексируют выполненные строки (`docs/session-search.txt`).

## Вне scope

Полный shell AST / heredoc / `$()`. Step-up MFA на SSH-команду в PTY.
