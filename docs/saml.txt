# KeepPAM: SAML 2.0 SSO

## Что есть

SP-initiated SAML 2.0 рядом с OIDC/LDAP/OAuth (режим взаимоисключающий: `local|oidc|ldap|saml|radius|oauth`).

1. Миграции `031` + `033` — IdP/SP, group→role, SLO URL в metadata.
2. `GET /api/v1/auth/saml/metadata` — SP metadata XML (ACS + SingleLogoutService).
3. `GET /api/v1/auth/saml/start` — AuthnRequest → redirect на IdP.
4. `POST /api/v1/auth/saml/acs` — assertion → provision/login. **IdP-initiated ACS** принимается без `/start` (`via=saml_idp`).
5. `GET|POST /api/v1/auth/saml/slo` — SP-initiated SLO (local logout всегда; редирект на IdP если в metadata есть SingleLogoutService).
6. Group→role: `saml_group_attr` + `saml_group_role_map` (не создаёт роли; `admin` не снимается).
   Имя IdP-группы = имя PAM-группы → членство добавляется (`docs/groups.txt`).
7. Login: кнопка на каждый готовый IdP (`docs/saml-idps.txt`).

При первом сохранении `mode=saml` генерируется RSA SP key (можно rotate).

## Настройка

1. Public Base URL = URL UI (стенд: `http://localhost:5173`).
2. В IdP зарегистрировать SP:
   - Entity ID / metadata: `{base}/api/v1/auth/saml/metadata`
   - ACS: `{base}/api/v1/auth/saml/acs` (HTTP-POST)
   - SLO: `{base}/api/v1/auth/saml/slo` (Redirect+POST)
3. В KeepPAM: IdP Metadata URL **или** Entity ID + SSO URL + signing cert PEM.
   SLO на IdP берётся **только из metadata URL** (ручной fallback SSO без SLO URL).
4. Group mapping (опц.): attr `groups`/`memberOf`, строки `IdP-group=keeppam-role`.
5. Сохранить → открыть Login.

## Вне scope

- Assertion encryption policy UI
- Несколько IdP одновременно — сделано, `docs/saml-idps.txt`
- IdP-initiated SLO (LogoutRequest от IdP)
- Создание ролей из групп
- Автоснятие PAM-группы, если IdP-группа пропала (без SCIM; inbound SCIM — `docs/scim.txt`)
